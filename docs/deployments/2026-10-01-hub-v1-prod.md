## Warnings / Pending

None of these blocked the release.

1. **PostgreSQL backups (Daily / Monthly).** The 2026-10-01 scheduled Daily and Monthly runs
   failed (task result `2`): the backup lock was held by another running backup (overlap). The
   Frequent tier keeps working. The most recent Daily and Monthly backups before the release are
   from 2026-09-29. Pending: find and remove the cause of the overlap and confirm the next
   scheduled Daily (2026-10-02 02:00) and Monthly runs.
2. **PROD Docker configuration.** The real PROD stack uses `compose.pilot.yaml` +
   `compose.prod-temp.yaml`, Docker project `daubert-hub` and port `8082`. `compose.prod-temp.yaml`
   exists only on the deployment host (excluded through `.git/info/exclude`, not versioned). It
   supplies `AUTH_COOKIE_SECURE` and the Payment Notifications reprocess webhook variables, which
   `compose.pilot.yaml` does not pass. The Compose project name `daubert-hub` is also the default
   project of `compose.yaml` (development `postgres-test`): running `down` or `up --remove-orphans`
   against it from that file would treat the PROD containers as orphans.
3. **Payment Notifications coverage.** There are specific coverage gaps for Payment Notifications
   that were known before the release and are not covered by an automated or documented manual
   test. One example identified in the audit is two payment receipts of the same provider with
   different ISO weeks in one e-mail/ZIP: the code groups them into one draft per provider and
   e-mail with a single payment date and one week of scheduled invoices. This was read from the
   workflow export but **not exercised in a real run**. It is a pending test, not a confirmed defect.
4. **Docker stack cleanup is out of scope.** Cleaning up or reorganizing the Docker stacks
   (separating the development `compose.yaml` project from PROD, versioning or replacing
   `compose.prod-temp.yaml`, aligning the TEST/PROD project names with the documentation) is
   deliberately **outside this release**.
